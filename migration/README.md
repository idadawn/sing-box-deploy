# 配置备份与接入服务器迁移

[migrate.sh](../migrate.sh) 用于加密导出或恢复 `.env` 和线路清单。需要让两台接入服务器并行运行、按线路切换已有订阅时，使用 [migrate-gw.py](../migrate-gw.py)。客户端更新订阅后，新连接使用新的入口；原有连接仍依赖旧机。

## 迁移前准备

| 项目 | 条件 |
| --- | --- |
| 源机与目标机 | 两台不同的 Linux/systemd 主机，CPU 架构一致。目标机可经 SSH 登录，主机密钥已核对，具备免交互 sudo、Python 3、OpenSSL、iproute2 和 useradd。目标机需留出独立服务所用的目录、服务名和监听端口。 |
| 网络与证书 | 目标机可以访问全部计划迁移的 SOCKS5 出口；在云安全组和主机防火墙开放相应 TCP、UDP 端口。证书覆盖原 TLS SNI，且在未来七天内有效。 |
| 订阅发布 | 有权限访问受保护的发布目录和现有专属订阅。准备私有的验证账号 JSON，权限为 `0600`，覆盖普通账号的线路权限；涉及管理员时另备管理员账号。 |
| 验证与状态 | 操作机准备 Python 3、Mihomo 和 Git 仓库之外的私有状态目录。另备源机、目标机和发布机的 SSH 参数、目标网卡名及全新的计量来源标识。 |
| 账期 | 若源机已启用按账号的供应商账期计量，现有并行迁移工具会拒绝准备目标机，需要单独安排目标供应商与账期接续。 |

## 分批切换

各操作的输入参数见 `python3 migrate-gw.py --help`。在同一次迁移中复用同一个私有 `--state` 目录。

1. **盘点**。用 `plan` 读取主机、发布配置和线路状态并保存快照。只需核查源机时可使用 `audit-source`。
2. **准备**。用 `prepare` 在目标机设置独立服务、规则和证书。为目标采集器建立新账本，源机继续处理已有连接并采集。
3. **验证**。用 `verify` 在临时客户端逐线路验证 Trojan、Hysteria2 和预期出口。包括公共直出时，核对目标机的公网出口。
4. **切换**。在验证通过后的 15 分钟内用 `switch --lines` 指定要切换的线路。发布后检查原有订阅链接、节点凭据、SNI、授权范围、用量响应头和目标机上报。超出验证窗口时重新运行 `verify`。
5. **观察与回退**。用 `status` 查看进度。需要回退单条或多条线路时使用 `rollback`。发布中断时保留私有日志并使用 `recover` 核对状态。发布器会检查并发修改，防止覆盖其他人的更新。
6. **交接**。两机并行期间由原续期方管理证书，续期后用 `sync-certs` 同步。在旧机退出前验证目标机能独立续期，并确认客户端已刷新、旧连接已排空、旧机已完成最终计量上报。仅凭 UDP 套接字数量无法判断会话是否排空。

导出包、验证账号、状态目录和恢复日志都可能包含凭据，请在私有位置备份。仓库回归可运行 `python3 tests/migration.py`，真实线路需要在目标环境另行验证。多来源账本的处理见[流量计量](../metering/README.md)。
