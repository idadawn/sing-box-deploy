# 订阅鉴权与账号

可选登录门户使用 Cloudflare Pages Functions 和 D1。用户通过一次性邀请设置密码，登录后可取得其授权线路的订阅。网页使用会话 Cookie，客户端使用独立、可撤销的订阅令牌，退出网页后客户端仍可按原链接更新。

## 启用前准备

- 一个用于鉴权发布的 Pages 项目和 D1 数据库。执行 [schema.sql](schema.sql)，将数据库绑定为 `SUB_AUTH_DB`，在私有配置中设置 `SUB_AUTH_D1_ID`。
- 至少 32 字节的随机 `SUB_AUTH_KEY`，保存为 Pages Secret 并私下备份。密码校验和订阅签名都依赖它。预览和正式环境分别使用各自的数据库与密钥。
- 一份账号到线路编号的授权清单。需要全线路权限的账号由服务端 `SUB_ADMIN_USERS` 指定。用量明细管理视图还要求有效的管理员网页会话。
- 使用私有目录保存邀请和验证文件。发布验证文件 `SUB_AUTH_VERIFY_FILE` 权限为 `0600`，至少准备两个已激活、授权范围不同的账号，填写 `username`、`scopes` 和各自的 `token`。
- 如启用按线路或按账号的独立节点凭据，在代理端和发布器准备相匹配的私有配置。涉及个人用量统计时，另见[流量计量](../metering/README.md)。

## 邀请与发布

1. 从仓库根目录运行下面的命令生成一个账号的邀请和 SQL。四个变量分别替换为自己的账号名、逗号分隔的线路编号、门户 HTTPS 源站和私有输出目录。

   ```bash
   node scripts/auth-invite.mjs "$ACCOUNT_NAME" "$LINE_SCOPES" "$PORTAL_ORIGIN" "$PRIVATE_DIR"
   ```

2. 把生成的 SQL 导入相应 D1，通过私有渠道交付邀请。邀请一天内有效且只能使用一次。先在隔离环境完成激活和权限验证。
3. 设置 `SUB_AUTH_ENABLED=true`，确认 D1、Secret 和验证文件齐全，再按 [Pages 发布说明](../cloudflare-pages-sub/README.md)发布。核对匿名请求被拒绝、各账号可下载自己的配置、跨账号请求被拒绝。首次启用失败时，修复绑定或权限后重新验证。
4. 若此前公开过订阅，逐一核查历史部署和别名，关闭仍可直接下载旧配置的入口。持有既有节点凭据的客户端仍可连接代理；撤销该能力需要协调轮换节点凭据。

## 运行行为

- 服务端在生成每份订阅时校验账号状态、令牌及线路范围。重置订阅令牌会撤销旧链接，禁用账号会阻止登录与订阅访问。
- Functions 私有模块承载凭据。构建器移除静态目录中包含凭据的文件。数据库或密钥缺失时拒绝访问。
- `SUB_LEGACY_RETIRED` 用于停用旧的公开订阅项目。先备份私有资产，配置目标门户地址，生成并验证关闭站点。旧下载应返回 HTTP 410，允许公开的规则文件仍可读取。持久化的关闭标记可防止后续规则同步重新发布旧订阅。
- 在仓库根目录运行 `bash tests/run.sh`。安装测试依赖后，运行 `node tests/auth-runtime.mjs` 和 `node tests/retired-runtime.mjs` 可在本地 Pages/D1 运行时验证登录和停用行为。依赖安装命令见 [CI](../.github/workflows/ci.yml)。
