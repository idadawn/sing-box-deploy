# 架构与路由

## 一条请求如何转发

客户端选择某条线路的 Trojan 或 Hysteria2 节点，接入服务器依据入站标识选择该线路的 SOCKS5 出口。线路编号把清单、生成的节点和出站规则关联起来。端口由清单行的位置和端口配置决定。修改客户端显示名称时，仍需保留服务端使用的标识。

普通流量和要求固定出口的流量经指定 ISP 转发。只有匹配已启用直连规则的流量才使用服务器公网出口。未匹配路由的流量由 `route.final=block` 拒绝。线路故障时，客户端可尝试同一线路的另一种协议；该线路的 SOCKS5 出口仍是共同依赖。

可选的公共直出服务使用独立的端口、凭据和订阅。客户端本地网络例外由客户端规则处理，两者的配置入口见[环境变量模板](../.env.example)。

## 订阅和账号

客户端从 Pages 获取配置，随后直接连接代理服务器。发布器按有效期生成线路清单和客户端配置。登录模式下，Pages Functions 根据账号授权范围生成响应，D1 保存账号、会话及用量记录。节点凭据和订阅下载令牌分别管理。详见[订阅鉴权](../subscription-auth/README.md)。

## 如何验证路由

1. 用 `sing-box check` 校验生成的候选配置，确认每条有效线路的两个入站都映射到正确的出站。
2. 对每条线路分别建立 Trojan 和 Hysteria2 连接，从客户端请求出口检查服务，核对预期的出口地址。
3. 如果启用了直连规则，用一项明确匹配的请求和一项普通请求分别验证。
4. 如果发布了订阅，重新导入或更新配置，确认节点、有效期、账号可见范围与测试结果一致。更换接入服务器时按[迁移指南](../migration/README.md)执行切换和回退。
